# Production migration from xterm.js to WTerm + Ghostty

## Summary

Replace xterm.js with WTerm and Ghostty as a complete terminal-engine migration, not a prototype. “Full Ghostty” means every VT behavior implemented by the pinned Ghostty v1.3.1 core and its tests; it does not include Ghostty’s native desktop UI. Kitty shared-memory transport `t=s` is the explicit exception: it will fail safely because the app’s tmux sessions share a process identity.

WTerm 0.5.0’s published Ghostty adapter does not cover several required browser and app behaviors, so package wiring alone is insufficient. Maintain a reviewed WTerm patch set and verify each added capability against the pinned source. [WTerm Ghostty docs](https://wterm.dev/ghostty), [pinned WTerm source](https://github.com/vercel-labs/wterm/commit/db938959543fe5f02b7c80d1b8837a1fdd6fa658).

## Implementation changes

- **Pin and ship reproducibly.** Lock `@wterm/react`, `@wterm/dom`, `@wterm/core`, and `@wterm/ghostty` to 0.5.0 at the reviewed source commit, and Ghostty to v1.3.1. Maintain repo-owned patches; pin Zig, build-container digests, and generated WASM hashes. Commit the built WASM, copy it to an explicit same-origin static path, and pass `wasmPath`. Require repeatable clean Linux builds and verify fetch and instantiation in the production Next webpack build and Docker runtime.

- **Replace the engine behind an adapter.** Add an internal terminal-engine adapter for resize, input, focus, selection, scrollback state, theme, and Ghostty replies. Preserve the public `TerminalHandle` API. Use one caller-owned Ghostty core per pane, explicitly dispose it on teardown, and make WTerm the sole fit owner. Keep hidden mobile panes at their last nonzero grid and refit before activation. Initialize and fit before connecting; the initial PTY size must be valid before tmux attach. Preserve `TERM=xterm-256color`, `COLORTERM=truecolor`, reconnect behavior, uploads and drops, file manager and preview, and selected-mobile-tab input ownership.

- **Patch the adapter to meet the feature matrix.** Cover all VT behavior implemented in the pinned Ghostty core. Add and test the missing app-facing paths, including mouse modes 1000/1002/1003 with SGR 1006, title updates, cursor shape/blink/color, indexed and dynamic palettes, cell geometry, fit metric refresh, bare URL links, touch scrolling, and full-history selection and copy. Fix the published input handler’s CJK IME and mobile keyboard behavior. A WASM failure must show a retryable error; it must not silently fall back to xterm or reduce scrollback.

- **Add a session-bound media bridge.** A same-origin POST accepts a tmux session name; the server resolves the live session and canonical registered working directory, plus `$TMPDIR` and `/tmp`, without accepting client-supplied paths. Issue a 256-bit, single-use capability expiring in 60 seconds, bound to the tmux server incarnation, immutable session ID, and allowed roots. On WebSocket `hello`, revalidate those bindings and attach by session ID before spawning the PTY. This makes rename safe and rejects stale tokens after a kill, recreation, or tmux server restart. Reject missing or invalid WebSocket Origins using the app’s Host and trusted forwarded-host logic; cover the deployed proxy host in the tests.

  The initial `hello` deadline is five seconds, with at most 32 pending handshakes. Validate dimensions on both client and server: integer columns 1–500, rows 1–300, and no more than 150,000 cells. Reject an invalid hello before PTY creation; close the PTY connection on invalid later resize. Keep existing JSON messages unchanged: `input/data`, `command/data`, `resize/cols/rows`, `output/data`, and `exit/code`.

  For Kitty `t=f` and `t=t`, the patched Ghostty core emits an async host-resource request after parsing the complete APC. The browser sends a versioned binary frame (`4-byte big-endian JSON-header length`, header up to 4 KiB, then optional bytes). Requests carry a unique ID, transport, source path or URL, offset, length, and format. The server acknowledges or rejects, streams chunks of at most 256 KiB with offsets and completion status, and accepts cancellation. On completion, the adapter supplies bytes to the original Ghostty image request and returns the standard Kitty result through the PTY input path; it does not reinject raw APC text. Cap each request at 32 MiB, use descriptor-relative access beneath the authorized roots, and read regular files only. Delete a `t=t` file only after a complete successful read, inside a permitted temp root, and with the Kitty temporary-file marker. Return an unsupported response for `t=s`; never access shared memory.

  URL transport is a documented **WTerm extension**, because Kitty’s standard transports are `d`, `f`, `t`, and `s`. [Kitty graphics protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/). Negotiate `WTERM_URL_IMAGE=1` via XTGETTCAP outside tmux. Inside managed tmux sessions, expose `@cliweb_wterm_url_image=1`; WTerm-aware clients query that session option because tmux handles XTGETTCAP itself. [tmux XTGETTCAP passthrough issue](https://github.com/tmux/tmux/issues/3755). Restrict URL fetches to HTTP(S) ports 80/443, reject credentials and private/reserved IPs, pin the validated DNS address to the actual connection, and repeat validation for up to three redirects. Limit each fetch to five seconds and 32 MiB of PNG. Allow at most four resource jobs per PTY and eight server-wide, with a 64 MiB global buffered/queued-byte ceiling, backpressure, and rejection on overload.

- **Preserve tmux key and graphics behavior.** Enable server-scoped `extended-keys` and append `xterm*:extkeys` without replacing existing `terminal-features`; tmux documents these settings for extended key forwarding. [tmux Modifier Keys](https://github.com/tmux/tmux/wiki/Modifier-Keys). Enable `allow-passthrough` only on app-managed session windows, including newly created windows, to forward wrapped Kitty graphics. [tmux FAQ](https://github.com/tmux/tmux/wiki/FAQ). Test Kitty keyboard protocol directly outside tmux and xterm extended keys inside it; do not claim tmux relays Kitty’s keyboard protocol. Preserve tmux’s configured shared-window sizing policy.

- **Handle clipboard writes deliberately.** For OSC 52 writes, keep only the latest pending payload per pane, capped at 16 MiB. Show a visible one-click Copy action and call the Clipboard API inside that gesture. If unavailable or denied, try a gesture-based fallback, then display selectable text for manual copying. Clear pending content on success or pane/session teardown. Do not expose clipboard reads.

## Test and release gates

- Build a traceable matrix from the exact Ghostty v1.3.1 VT implementation and fixtures. Missing browser mappings or failing supported sequences block release.
- Verify PTY resize, typing, tmux mouse scrolling and copy mode, alternate screen, keyboard negotiation, palette/title/cursor behavior, scrollback reflow, and select-all. Retain at least 15,000 displayed history rows at 40, 80, 120, and 240 columns with ASCII, CJK, styled, and wrapped output. Choose the smallest byte budget that meets that retention; do not silently lower the row count.
- Exercise file and URL graphics in actual tmux sessions, including image placement and replies. Test traversal, symlinks, disallowed roots, temp cleanup, private IPs, DNS rebinding, redirects, oversize and truncated files, timeouts, cancellation, quota exhaustion, proxy Origins, expired/reused tokens, session rename/recreation, server restart, malformed headers, oversized dimensions, and disconnect cleanup.
- Verify upload/drop, file-manager media previews, reconnect and visibility recovery, mobile focus ownership, and layout at one, two, and three monitor panes. Test two clients with unequal PTY sizes and confirm the shared grid follows tmux’s configured policy.
- Test production WASM loading in Docker and the Next build. Cover desktop Chrome and Firefox, Windows CJK IME, physical iOS Safari keyboards, and Android Chrome keyboards.
- Compare against the pinned xterm baseline using five paired 10-minute loopback runs: input-to-painted p95 at most 100 ms, no foreground stall over 250 ms, and no more than 20% p95 regression. At 15,000 rows and one to three panes, peak page/renderer memory must stay within 1.25× the xterm baseline and plateau after output stops. Any failed gate blocks the replacement.

## Assumptions and artifact

The approved filesystem boundary is each live tmux session’s registered working directory plus `$TMPDIR` and `/tmp`; paths outside those roots fail. `t=s` remains unsupported by explicit choice. All other behavior in the pinned Ghostty VT core is in scope.
